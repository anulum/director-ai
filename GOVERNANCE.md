# Governance

## Project Lead

**Miroslav Šotek** ([@anulum](https://github.com/anulum))
ORCID: [0009-0009-3560-0851](https://orcid.org/0009-0009-3560-0851)

All architectural decisions, release approvals, and security responses
are made by the project lead.

## Decision Process

1. **Minor changes** (typos, docs, test additions): merge after CI passes.
2. **Feature additions**: open an issue first for discussion, then PR.
3. **API changes**: require explicit approval from the project lead.
4. **Security patches**: fast-tracked, coordinated via private email.

## Release Cadence

Releases follow [Semantic Versioning](https://semver.org/). Patch releases
ship as needed for bug fixes. Minor releases target monthly cadence.
Major releases are planned with deprecation notices.

## Repository Ownership

The repository belongs to [@anulum](https://github.com/anulum). Miroslav Šotek
is responsible for code review, CI health, and release management. The
[CODEOWNERS file](.github/CODEOWNERS) routes file reviews to that account.
